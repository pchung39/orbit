ORBIT · Spacecraft anomaly investigation

From spacecraft alarm to a decision you can check.

ORBIT seals a telemetry window for the case, weighs the possible causes against the named procedure, and replays each option in a simulator before anyone acts. Operators see what happened and why, choose a next step—including holding for more evidence—and check that the fix worked.

Designed and built by Paul Chung

Product manager and software engineer with experience building spacecraft ground software and test automation at NASA JPL.

The decision that shaped the product

Similar alarms. Different next steps.

Both cases trigger a low-voltage warning. Both include a payload entering science mode, which makes the payload look guilty. The deciding evidence is whether heater current meets the procedure’s threshold for naming it the prime suspect.

Open the hold case

A useful investigator must recognize when the evidence supports an action—and when it does not. I built the hold case first to make that requirement explicit.

An operator makes the decision. ORBIT cannot send spacecraft commands; previews and verification run in a simulator.

How it works

An investigation you can follow.

  1. 01

    Seal the window

    Cut a fixed window from the archive tape and write it with the case. Every measurement on the case page reads from that sealed file, not a live archive query.

  2. 02

    Weigh every explanation

    Check heater, payload, and battery against the one procedure that governs the alarm. Each cause gets evidence for and against, and each line links to the moment on the chart.

  3. 03

    Preview the options

    Replay the same window in the simulator: with the suspect fault removed, and with each possible action taken. See what happens next before anyone decides.

  4. 04

    Decide, verify, close

    The operator approves an option or holds. ORBIT records the decision, checks the result against the procedure’s recovery step, and keeps a hold open as Watching.

Where the AI fits

The investigator decides what to sample from the sealed tape, which named document to read, and whether those results meet the procedure’s threshold for a recommendation.

The browser demo uses a rules-based investigator so the reference behavior is repeatable. Experimental LLM providers are available on the command line. Published evaluation results cover the rules-based provider only.

The previews are not AI. Each scenario is a seeded physics simulation, so replaying it reproduces the tape exactly; changing one thing shows what that change would do.

Evaluation

A correct answer is only part of the test.

The suite checks both the decision and the evidence supporting it. A report can reach the expected conclusion and still fail because its claims are unsupported or its recommendation is inappropriate.

  • Outcome

    Does the cause and recommended action match the expected result?

  • Hold behavior

    When the evidence is insufficient, does the investigator hold and explain what is missing?

  • Evidence support

    Do claims have the required source labels, calculations, and citations?

  • Alternative cases

    Does the investigator avoid a heater inhibit when that action is inappropriate?

Designated failures block release even when the overall score improves. Separate tests check that the currents quoted on the case page are samples from the tape and that each simulator replay reproduces its tape exactly.

These results cover a small regression suite using simulated data. They do not establish LLM performance, reliability on real flight data, or readiness for operational use.
